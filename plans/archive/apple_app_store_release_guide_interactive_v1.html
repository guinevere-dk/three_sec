  • CI/Codemagic/fastlane 설정 초안 작성.

3. iOS 출시 핵심 개념

Bundle ID / App ID

앱의 주민등록번호입니다. 이 저장소의 값은 com.dk.three_sec입니다. App Store Connect, Firebase iOS 앱, Apple Developer Identifiers, Xcode Signing이 모두 같은 값을 바라봐야 합니다.

Certificates

“이 개발자가 만든 앱이 맞다”는 전자 도장입니다. Xcode 자동 관리 또는 CI 비밀값으로 관리합니다.

Provisioning Profile

Bundle ID + 인증서 + Capability를 묶은 배포 허가증입니다.

Xcode Signing

Xcode의 Signing & Capabilities에서 Team과 자동 서명, Apple 로그인, Push 등을 확인합니다.

Archive / IPA

App Store에 올리는 배포 파일입니다. Flutter에서는 flutter build ipa --release 또는 Xcode Archive로 만듭니다.

TestFlight

심사 전 실제 iPhone에서 테스트하는 공식 배포 채널입니다.

6. Firebase/Auth/Firestore/Storage/Functions 출시 전 점검

금지: Firebase project id fir-3s-8edb9, 컬렉션 users/videos/vlog_projects, Storage 경로 users/{uid}/videos/{videoId}/{fileName}를 바꾸지 않습니다.

필수 체크

  • Firebase Console에 iOS 앱 Bundle ID com.dk.three_sec 등록.
  • GoogleService-Info.plist를 iOS 타깃에 포함.
  • Firebase Auth Apple/Google provider와 소셜 로그인 구성 확인.
  • Firestore rules는 본인 uid 조건 유지. 보안 완화 금지.
  • Storage rules는 본인 uid, 파일 타입, 500MB 제한 유지.
  • Functions social 함수가 /exchange와 /iap/verify 경로 제공.

TestFlight에서 꼭 볼 증상

  • Firebase 초기화 실패 로그 없음.
  • Apple 로그인 후 Firebase uid 생성 및 프로필/구독 상태 유지.
  • 클라우드 업로드/다운로드/삭제가 본인 계정에서만 가능.
  • 동일 계정 재로그인 시 라이브러리/프로젝트 구조 복원.
  • SOCIAL_AUTH_EXCHANGE_URL이 릴리스 빌드에 주입.

구독 심사에서 자주 보는 항목
  • 가격, 기간, 자동 갱신 여부가 구매 전 화면에 명확한지.
  • 구매 복원 버튼이 보이고 동작하는지.
  • Apple 계정 설정에서 해지 가능하다는 안내가 있는지.
  • 무료/유료 기능 경계가 명확한지.
  • 외부 결제 우회가 없는지.
현재 코드 기준 리스크
  • 클라이언트는 iOS receipt를 /iap/verify로 전송하지만 Functions는 verificationMode: schema_and_business_rule_only를 반환합니다.
  • 첫 출시 전 Apple 서버 영수증 검증 강화 여부를 별도 승인 작업으로 판단해야 합니다.
  • iOS Sandbox 계정으로 구매/복원/만료/업그레이드/다운그레이드를 테스트해야 합니다.

1. 앱 실행 후 게스트 모드 또는 제공된 테스트 계정으로 진입합니다.
