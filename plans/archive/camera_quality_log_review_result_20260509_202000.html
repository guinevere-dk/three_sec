부분 만족 근거

전체 세션 로그

full.log는 앱 실행, 카메라 상태, 저장/정규화 요청, 런타임 종료 이벤트를 폭넓게 포함합니다. 목표 파라미터와 위험 이벤트가 함께 확인됩니다.

  • targetFps=30, targetBitrate=12000000, codec=h264 반복 확인
  • normalizeVideoDuration complete 및 saveGatePass=true 확인
  • sourceDurationMs, normalizedDurationMs는 있으나 실제 처리시간과 파일 크기는 없음
추가 해석⌄
정규화 완료 자체는 확인되지만 실제 export complete, outputPath별 fileSize, actualBitrate, color metadata가 없으므로 품질 개선 검증으로 보기에는 부족합니다.
위험

에러 로그

errors.log에서 썸네일 플러그인 채널 오류, 앱 사망, Surface 정리, CAMERA AppOps 실패가 확인됩니다.

  • MissingPluginException(No implementation found for method data on channel plugins.justsoft.xyz/video_thumbnail)
  • Force removing ActivityRecord... app died, no saved state
  • destroySurfaces: appStopped=true, Operation not started... op=CAMERA
위험 영향⌄
앱이 죽거나 재설치/패키지 제거 이벤트가 섞이면 단일 실행 세션의 품질 측정 신뢰도가 떨어집니다. 플러그인 등록 문제는 라이브러리/썸네일 화면 안정성에도 영향을 줄 수 있습니다.
확인 + 미확인

앱 신호 로그

appsignals.log는 Flutter 앱 레벨 이벤트가 압축되어 있어 목표 파라미터 확인에 가장 직접적입니다.

  • recorded_clip_enqueued ... quality=1080p · 30fps · 12Mbps
  • saveRecordedVideo_paths ... quality=1080p targetFps=30 targetBitrate=12000000 codec=h264
  • thumbnail_error가 동일 세션에 발생
미확인 항목⌄
color metadata, actualBitrate, 파일 크기, 처리시간, 8/16Mbps 대조군, AE/AWB/AF lock 상태는 앱 신호 로그에서 확인되지 않습니다.
시스템 상태

앱 전체 로그

appfull.log는 CameraService, WindowManager, SurfaceFlinger, AppOps 등 플랫폼 이벤트를 포함합니다.

  • 카메라 OPENING → OPEN → ACTIVE → IDLE → CLOSED 전이가 확인됨
  • minFPS = 30.000002, maxFPS = 60.0 범위 등록 확인
  • 앱 종료 시 app died, CAMERA AppOps 실패가 뒤따름
품질 검증 관점⌄
플랫폼 카메라 활성화는 확인되지만, 노출/화이트밸런스/포커스 수렴값이나 lock 성공 여부는 앱 레벨 별도 로그 없이는 판정할 수 없습니다.
보조 근거

진단 로그

diagnostics.log는 세션 재현과 환경 확인을 위한 보조 자료입니다. 본 검토에서는 핵심 품질 실험 결과보다 안정성/수집 완전성 판단에 사용했습니다.

  • 단일 실행 세션의 연속성이 중요하므로 앱 교체/재설치 이벤트 혼입 여부 확인 필요
  • 품질 산출물의 JSON 스키마 로그가 별도 보강되어야 함
  • 진단 로그만으로 LUT/후처리 PoC나 bitrate 비교를 만족 처리할 수 없음
다음 수집 조건⌄
동일 앱 설치 상태에서 녹화 → 정규화 → 썸네일 → 라이브러리 렌더 → 종료까지 단일 세션으로 수집하고, 각 샘플별 JSON 결과를 남기는 것이 필요합니다.
