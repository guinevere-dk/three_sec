# Cloud 백업/복원 릴리스 확인 체크리스트 v1

## 1. 정책 확정 요약

- 구독이 만료되기 전 사용자가 필요한 Cloud 백업을 다운로드/복원해야 한다.
- 구독이 만료되면 할당된 Cloud와 기존 Cloud 백업이 삭제되므로, 만료 후에는 기존 Cloud 백업을 다운로드할 수 없다.
- 만료 후 기존 Cloud 백업을 읽기 전용으로 다운로드 허용하는 정책은 채택하지 않는다.
- 앱 문구, 권한 정책, QA 기준은 모두 “만료 전 복원”을 기준으로 정렬한다.
- 만료 후 접근 불가 정책은 실제 서버, Functions, 운영 프로세스와 일치해야 하며, 사용자 데이터 삭제가 포함될 수 있으므로 별도 승인과 검증 없이 구현하지 않는다.

## 2. 사용자가 확인해야 할 체크리스트

- [ ] 실제 Standard 이상 계정에서 Cloud 보관함 목록 조회가 가능하다.
- [ ] Cloud 보관함에서 선택 복원을 실행하면 복원이 성공하고 Library에 반영된다.
- [ ] 이미 복원된 항목을 재복원할 때 건너뜀 또는 중복 완화 동작이 적용된다.
- [ ] `storagePath`가 없는 레거시 문서는 복원 불가할 수 있음을 확인했다.
- [ ] 구독 해지/만료 안내 문구가 “만료 전 다운로드” 필요성을 충분히 명확하게 전달한다.
- [ ] 앱 삭제/재설치 후 로그인하면, 구독 만료 전에는 Cloud 보관함 접근과 복원이 가능하다.
- [ ] 구독 만료 후 Cloud 데이터 삭제/접근 불가 정책이 실제 서버, Functions, 운영 프로세스와 일치한다.
- [ ] Firestore/Storage rules와 index 변경은 아직 별도 승인 필요 항목으로 남아 있다.

## 3. QA 시나리오

### 3.1 정상 복원

- [ ] Standard 이상 계정으로 로그인한다.
- [ ] Cloud 보관함 목록을 조회한다.
- [ ] 복원할 항목을 선택한다.
- [ ] 복원 완료 후 Library에서 항목이 표시되는지 확인한다.
- [ ] 복원된 항목의 재생, 썸네일, 앨범/폴더 표시가 기대대로 동작하는지 확인한다.

### 3.2 네트워크 중단/재시도

- [ ] 복원 진행 중 네트워크를 중단한다.
- [ ] 실패 안내 또는 대기 상태가 사용자에게 명확히 표시되는지 확인한다.
- [ ] 네트워크 복구 후 재시도한다.
- [ ] 재시도 후 중복 파일이 생성되지 않거나 중복 완화 정책이 적용되는지 확인한다.

### 3.3 용량 부족

- [ ] 기기 저장 공간이 부족한 상태에서 복원을 시도한다.
- [ ] 용량 부족 오류가 사용자에게 명확히 표시되는지 확인한다.
- [ ] 실패한 항목이 부분 복원 상태로 잘못 표시되지 않는지 확인한다.
- [ ] 공간 확보 후 재시도 가능 여부를 확인한다.

### 3.4 중복 복원

- [ ] 이미 복원된 Cloud 항목을 다시 선택한다.
- [ ] 동일 항목이 무제한 중복 생성되지 않는지 확인한다.
- [ ] 건너뜀, 덮어쓰기 방지, 동일 항목 안내 등 중복 완화 동작이 확인된다.

### 3.5 구독 만료 전/후

- [ ] 구독 만료 전에는 Cloud 보관함 목록 조회와 선택 복원이 가능하다.
- [ ] 구독 만료 전 안내 문구가 “만료 전 다운로드/복원 필요”를 명확히 전달한다.
- [ ] 구독 만료 후에는 Cloud 할당/백업 삭제 정책에 따라 기존 Cloud 백업 다운로드가 불가능하다.
- [ ] 구독 만료 후 읽기 전용 다운로드 허용 정책이 앱 문구나 권한 정책에 남아 있지 않다.

### 3.6 앱 삭제 후 재설치

- [ ] 앱을 삭제한다.
- [ ] 앱을 재설치한다.
- [ ] 동일 계정으로 로그인한다.
- [ ] 구독 만료 전에는 Cloud 보관함 접근과 복원이 가능한지 확인한다.
- [ ] 구독 만료 후에는 Cloud 데이터 삭제/접근 불가 정책에 맞게 접근이 차단되는지 확인한다.

## 4. 남은 승인 필요 항목

- [ ] Firebase rules/index 변경.
- [ ] 만료 시 Cloud 삭제 자동화, 스케줄러, Functions 검증.
- [ ] 레거시 `downloadUrl` only 문서 처리 정책.
- [ ] 로컬 인덱스 schema 확장 여부.

## 5. 완료 기준

릴리스 전 사용자가 아래 항목을 수동으로 확인하고 완료 표시한다.

- [ ] 정책 문구가 “만료 전 다운로드/복원 필요” 기준으로 정리되었다.
- [ ] 만료 후 읽기 전용 Cloud 백업 다운로드 허용 정책이 문서, 앱 문구, 권한 정책에서 제외되었다.
- [ ] 실제 Standard 이상 계정에서 Cloud 보관함 목록 조회를 확인했다.
- [ ] 선택 복원 성공 및 Library 반영을 확인했다.
- [ ] 중복 복원 시 건너뜀 또는 중복 완화 동작을 확인했다.
- [ ] `storagePath`가 없는 레거시 문서의 복원 불가 가능성을 확인했다.
- [ ] 구독 해지/만료 안내 문구가 만료 전 다운로드 필요성을 충분히 전달한다고 확인했다.
- [ ] 앱 삭제/재설치 후 로그인하여 만료 전 Cloud 보관함 접근과 복원이 가능한지 확인했다.
- [ ] 만료 후 Cloud 데이터 삭제/접근 불가 정책이 서버, Functions, 운영 프로세스와 일치한다고 확인했다.
- [ ] Firebase rules/index 변경은 별도 승인 전까지 보류한다고 확인했다.
- [ ] 만료 시 Cloud 삭제 자동화/스케줄러/Functions 검증은 별도 승인 전까지 보류한다고 확인했다.
- [ ] 레거시 `downloadUrl` only 문서 처리 정책은 별도 확정 전까지 보류한다고 확인했다.
- [ ] 로컬 인덱스 schema 확장 여부는 별도 승인 전까지 보류한다고 확인했다.

## 6. 변경 금지 및 보류 확인

- 이 문서는 확인용 Markdown 문서이며, 코드, Firebase rules/index, Functions, 플랫폼 설정을 변경하지 않는다.
- 기존 legacy identifier는 변경하지 않는다.
- Firestore 컬렉션명, Storage path, SharedPreferences key, IAP product id는 별도 승인, dry-run, 백업, 롤백 계획 없이 변경하지 않는다.
