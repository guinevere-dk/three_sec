1. 현재 준비된 파일 요약

이 작업에서는 가이드 HTML만 생성하며 Firebase/project/applicationId/규칙/데이터 관련 설정은 변경하지 않습니다.

firebase.json Hosting public 경로가 firebase/hosting으로 설정되어 있습니다. Firestore, Storage, Functions 설정은 이 가이드 작업 범위에서 변경하지 않습니다.
firebase/hosting/app-update.json 앱 업데이트 설정 JSON입니다. 현재 latestVersion과 minimumRequiredVersion은 모두 1.3.5입니다.
plans/firebase_hosting_app_update_config_guide.md 기존 Markdown 가이드입니다. 삭제하지 않고 유지하며, 이 HTML은 해당 내용을 인터랙티브 형식으로 재구성합니다.
기본 JSON은 강제 업데이트를 실수로 발생시키지 않도록 현재 앱 버전 기준값인 1.3.5와 동일하게 맞춰져 있습니다.

2. 사용자가 직접 해야 할 단계별 체크리스트

각 항목을 완료할 때마다 체크하면 좌측 진행률이 갱신됩니다. 체크 상태는 이 브라우저의 로컬 저장소에만 보관됩니다.

3. Firebase Hosting 활성화, 로그인, 프로젝트 확인, 배포, URL 확인 절차

3.1 CLI 설치와 로그인

Firebase CLI 설치
npm install -g firebase-tools
Firebase 로그인
firebase login

3.2 프로젝트 확인

프로젝트 목록과 현재 alias 확인
firebase projects:list
firebase use

현재 저장소의 기본 프로젝트 alias는 .firebaserc 기준 fir-3s-8edb9입니다. 이 값은 승인 필요 대상이므로 가이드 절차 중 임의 변경하지 않습니다.

3.3 Hosting 활성화

  1. Firebase Console에서 대상 프로젝트를 선택합니다.
  2. Hosting 메뉴로 이동합니다.
  3. 아직 활성화되지 않았다면 “시작하기”로 사이트를 생성하거나 연결합니다.
  4. project id 또는 site id 변경이 필요하면 별도 승인, 영향도 분석, 롤백 계획을 먼저 준비합니다.

3.4 Hosting만 배포

필수 배포 명령
firebase deploy --only hosting

이 명령은 Hosting만 배포합니다. Firestore, Storage, Functions는 이 절차에서 배포하지 않습니다.

3.5 배포 URL 확인

일반적인 URL 형식은 다음 중 하나입니다. 실제 Hosting site id가 다를 수 있으므로 배포 결과 또는 Firebase Console에 표시된 URL을 최종 기준으로 사용합니다.

예상 URL
https://fir-3s-8edb9.web.app/app-update.json
https://fir-3s-8edb9.firebaseapp.com/app-update.json
JSON 응답 확인
curl https://fir-3s-8edb9.web.app/app-update.json
4. Flutter 릴리스 빌드에 APP_UPDATE_CONFIG_URL 연결

앱 업데이트 체크는 릴리스 빌드 시 APP_UPDATE_CONFIG_URL이 비어 있지 않을 때 활성화됩니다. 실제 명령에는 배포 후 확인한 Hosting URL을 사용합니다.

App Bundle 릴리스 빌드
flutter build appbundle --release --dart-define=APP_UPDATE_CONFIG_URL=https://fir-3s-8edb9.web.app/app-update.json
APK 릴리스 빌드
flutter build apk --release --dart-define=APP_UPDATE_CONFIG_URL=https://fir-3s-8edb9.web.app/app-update.json

5. JSON 값 입력 시 업데이트 결과 미리보기

정책: minimumRequiredVersion은 강제 업데이트 기준, latestVersion은 선택 업데이트 기준입니다. 현재 앱 버전이 minimumRequiredVersion보다 낮으면 강제 업데이트, 그렇지 않고 latestVersion보다 낮으면 선택 업데이트입니다.

업데이트 없음

현재 버전과 기준 버전이 동일합니다.

업데이트 다이얼로그가 뜨지 않는 설정입니다.

생성될 JSON 미리보기

app-update.json
6. 선택 업데이트, 강제 업데이트, 롤백 운영 예시
상황JSON 운영값결과주의사항
업데이트 없음 latestVersion=1.3.5
minimumRequiredVersion=1.3.5		 1.3.5 사용자에게 업데이트 다이얼로그가 뜨지 않습니다. 초기 배포와 안전 기본값에 적합합니다.
선택 업데이트 latestVersion=1.3.6
minimumRequiredVersion=1.3.5		 1.3.5 사용자는 선택 업데이트 안내를 받을 수 있습니다. Play Store에 1.3.6이 배포된 뒤 적용합니다.
강제 업데이트 latestVersion=1.3.6
minimumRequiredVersion=1.3.6		 1.3.5 이하는 강제 업데이트 대상입니다. 심각한 장애 또는 정책 이슈에만 사용하고, Store 전파 후 적용합니다.
JSON 값 롤백 minimumRequiredVersion을 현재 운영 앱 버전 이하로 낮춤 잘못 켠 강제 업데이트를 완화합니다. 수정 후 firebase deploy --only hosting으로 Hosting만 재배포합니다.
Hosting 릴리스 롤백 Firebase Console의 Hosting 릴리스 히스토리에서 직전 정상 릴리스 선택 이전 정상 JSON으로 되돌릴 수 있습니다. CDN/클라이언트 캐시 영향을 앱에서 재확인합니다.

7. 실수 방지 경고와 변경 금지 항목

Play Store에 새 버전이 실제로 배포되고 충분히 전파되기 전에는 minimumRequiredVersion을 상향하지 마세요. 사용자가 업데이트할 수 없는 상태에서 강제 업데이트가 걸릴 수 있습니다.
이 절차 중 Firebase project id, alias, 앱 등록, 서비스 계정, Android applicationId, iOS bundle id, Firestore/Storage rules, 데이터 schema, IAP product id를 임의 변경하지 않습니다.
  • com.dk.three_sec applicationId는 Play Store URL과 앱 식별 계약에 연결되어 있으므로 유지합니다.
  • fir-3s-8edb9 project id/alias는 승인 필요 대상입니다.
  • Firestore/Storage/Functions 배포를 Hosting 배포와 섞지 않습니다.
  • 사용자 원본 영상, 프로젝트 메타데이터, 클라우드 백업 경로에 영향을 주는 변경은 이 가이드 범위가 아닙니다.
  • 버전 문자열은 앱 파서에 맞춰 major.minor.patch 형식으로 작성합니다. 예: 1.3.6.
