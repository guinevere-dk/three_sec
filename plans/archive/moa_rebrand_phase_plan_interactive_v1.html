Executive Summary

결론

  • 신규 사용자 노출 브랜드는 MOA로 고정한다.
  • 앱 설명은 2초 촬영으로 모아 만드는 Vlog 계열로 정렬한다.
  • One Second Vlog, 1s Vlog, 원세컨 브이로그, Three Sec Vlog, 3s는 사용자 노출에서 제거한다.
  • com.dk.three_sec, fir-3s-8edb9, 3s_*, vlog_projects, vlog_folders는 레거시 호환 키로 분류하고 즉시 변경하지 않는다.
  • 현재 워크스페이스 폴더명 three_sec_vlog은 툴 내 파일 변경 범위 밖으로 보며, 별도 운영 절차로 IDE/CI/로컬 캐시 재검증 후 변경한다.

검토 근거

기존 문서는 3초 → 1초 → 2초 정책이 순차적으로 존재하며, 최신 정체성은 2초 정책 문서의 kTargetClipMs=2000, 2s 라벨 방향에 맞춘다. Firebase 계약은 uid 기반 데이터 분리, Storage users/{uid}/videos/{videoId}/{fileName}, 주요 컬렉션/필드 불변 원칙을 유지한다.

변경 원칙

  1. 브랜드와 시간 정책 분리: 브랜드명은 MOA, 제품 카피는 2초 촬영 + Vlog로 정렬한다.
  2. 사용자 노출 먼저: 앱 표시명, 온보딩, 웹 manifest, README/릴리즈 문구 등 사용자 인지 영역부터 바꾼다.
  3. 식별자·DB 키는 보수적으로: package/bundle/Firebase/IAP/Firestore/Storage/local key는 호환성과 롤백을 확보한 후 별도 Phase에서 결정한다.
  4. dual-read/write 우선: 새 키 도입이 필요하면 기존 키 read 유지, 새 키 write 병행, 백필, 검증, 구 키 freeze 순서로 간다.
  5. 보안 규칙 완화 금지: Firebase 보안 규칙은 완화하지 않고, 변경 시 더 엄격하거나 동등한 조건으로만 검증한다.
  6. 상품 ID 변경 금지: 3s_standard_monthly 등 IAP product ID는 구독 승계 리스크가 매우 커서 표시명만 변경한다.

Phase 0~6 실행 계획

Phase 0 · 기준선 고정과 자동 스캔

중간
목적: 변경 전 기준선 확보대상: 문서/코드/설정 전체

사용자 노출, 내부 레거시, DB/Storage, 패키지/번들, Firebase/IAP를 분류하는 inventory를 확정한다. 실제 변경은 하지 않는다.

실행·검증·완료 기준
  • 변경 방식: Select-String 기반 검색 결과를 inventory로 저장하고, 사용자 노출/레거시/보류로 태깅.
  • 검증 명령: flutter analyze는 아직 실행하지 않고, 검색 명령과 HTML 정적 검증 우선.
  • 완료 기준: 금지어, 키, 패키지명, Firebase alias, DB 컬렉션 목록이 Phase별로 분류됨.
  • 롤백 조건: 없음. 계획 문서만 생성.

Phase 1 · 사용자 노출 브랜드 전환

낮음
목적: MOA 인지 통일대상: 앱명/온보딩/웹 manifest/스토어 카피

원세컨, One Second, 1s, 사용자 노출 3s를 MOA와 2초 Vlog 문구로 교체한다. 내부 키는 건드리지 않는다.

실행·검증·완료 기준
  • 대상 파일: lib/main.dart, lib/screens/login_screen.dart, lib/screens/announcements_screen.dart, lib/screens/profile_screen.dart, android/app/src/main/AndroidManifest.xml, web/manifest.json.
  • 변경 방식: 문자열만 변경, 기능 로직/키/식별자 변경 금지.
  • 검증 명령: flutter analyze, flutter test, 주요 화면 스크린샷 QA.
  • 완료 기준: 사용자 화면에서 1초/원세컨/Three Sec/3s 브랜드 노출 0건, 2초 촬영 설명 유지.
  • 롤백 조건: 앱 표시명/문구 혼선, 스토어 심사 이슈 발생 시 이전 카피 revert.

Phase 2 · 문서·디자인·운영 메타 정렬

중간
목적: 정책 근거 통일대상: README, plans, benchmark, 릴리즈 노트

최신 정책 문서에는 MOA와 2초 촬영 + Vlog를 기준으로 명시하고, 과거 문서의 1초/3초 명칭은 역사적 문맥 또는 legacy/as-is로 분류한다.

실행·검증·완료 기준
  • 검증 명령: 문서 검색, 링크 확인, HTML/Markdown 프리뷰.
  • 완료 기준: 신규 문서에서 금지 표기 사용 금지, 과거 문서 인용은 legacy 라벨 포함.
  • 롤백 조건: 정책 충돌 발견 시 해당 문서만 revert.

Phase 3 · 로컬 키/경로 호환 마이그레이션 설계

높음
목적: 로컬 호환성 보존대상: SharedPreferences, local index, cache path

three_sec_vlog, three_s, vlog_* 계열 로컬 키는 삭제하지 않고, 새 moa_* 키를 도입할 필요가 있을 때만 dual-read/write로 이동한다.

실행·검증·완료 기준
  • 변경 방식: dry-run scanner → backup export → dual-read old/new → write new + old 유지 → mismatch 로그 → staged rollout.
  • 검증: 앱 업그레이드, 로그아웃/재로그인, 계정 전환 잠금, 오프라인 캐시 복원.
  • 완료 기준: 기존 사용자 로컬 영상/프로젝트 노출 정상, 타 계정 데이터 직접 노출 0건.
  • 롤백 조건: 누락률, lockState 불일치, path resolve 실패 발생 시 old-read only로 전환.

Phase 4 · DB/Firebase/Storage 마이그레이션 전략

높음
목적: 데이터 유실 없는 서버 계약 변경 가능성 검증대상: Firestore, Storage, Functions

컬렉션/필드/Storage path 변경은 기본 보류한다. 꼭 필요할 경우 v2 계약서를 먼저 발행하고 emulator dry-run, 백업, dual-write, 백필, rollback alias를 준비한다.

실행·검증·완료 기준
  • 대상 키: vlog_projects, videos.storagePath, projects.folderName, users/{uid}/videos/{videoId}/{fileName}.
  • 검증 명령: firebase emulators:start, firebase deploy --only firestore:rules는 실제 배포 전 dry-run/스테이징에서만.
  • 완료 기준: 샘플 uid 백업·복구 성공, old/new read 결과 동일, 규칙 완화 없음.
  • 롤백 조건: permission denied 증가, 누락 문서, 다운로드 URL 불일치, sync fail rate 임계 초과.

Phase 5 · 기술 식별자 변경 여부 결정

매우 높음
목적: 바꿀지 말지 결정대상: package, bundle, Firebase app, OAuth, IAP

권장 기본값은 유지다. 변경이 필요하면 브랜드 전환과 분리된 독립 프로젝트로 수행하고 스토어 신규 앱 취급 가능성을 먼저 확정한다.

실행·검증·완료 기준
  • 대상: com.dk.three_sec, PRODUCT_BUNDLE_IDENTIFIER, fir-3s-8edb9, 3s_*.
  • 검증: 내부 트랙, 소셜 로그인, 결제 검증, 푸시, 딥링크, 기존 설치 업데이트.
  • 완료 기준: 변경 유지/보류 의사결정 문서 승인.
  • 롤백 조건: 로그인/결제/업데이트 체인 실패, Firebase app mismatch.

Phase 6 · roo folder/저장소명 운영 변경

중간
목적: 외부 명칭 정리대상: 폴더명, IDE, CI, 문서 경로

현재 작업 루트 three_sec_vlog 변경은 파일 패치 범위 밖일 수 있다. 별도 운영 창에서 clone path, IDE module, CI workspace, 문서 링크를 점검한다.

실행·검증·완료 기준
  • 절차: 브랜치 freeze → 클린 clone to moa_vlog 또는 moa → IDE import → scripts path 점검 → CI 실행.
  • 검증: flutter pub get, flutter analyze, flutter test, Functions lint.
  • 완료 기준: 절대 경로 의존 0건, 팀 문서/CI 경로 업데이트.
  • 롤백 조건: IDE/CI/빌드 경로 깨짐 발생 시 기존 폴더명 유지.

DB/Firebase/Storage 마이그레이션 플로우

1. Freeze & Backup

변경 전 Firestore export, Storage manifest, 로컬 인덱스 샘플 백업.

2. Dry-run

Emulator와 샘플 uid에서 old/new mapping 결과 비교.

3. Dual-read/write

구 키 read 유지, 새 키 write 병행. mismatch telemetry 수집.

4. Backfill

배치 단위 백필. 실패 항목은 재시도 큐와 rollback token 보존.

5. Cutover/Rollback

임계치 통과 시 전환. 실패 시 old-read only와 백업 복구.
